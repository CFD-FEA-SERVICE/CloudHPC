# damBreak-v2412 — OpenFOAM v2412 · collapsing water column

The classic volume-of-fluid benchmark: a column of water held against the left
wall of a tank is released at t = 0, collapses under gravity, runs along the
floor and slams into a small obstacle. `interFoam` tracks the air/water
interface by solving a transport equation for the water fraction `alpha.water`.

This example is deliberately built on the **ESI/OpenCFD** lineage (`v2412`)
rather than the Foundation one, because the two differ in ways that bite when a
case is moved between them:

| | Foundation (`of10` … `of14`) | ESI/OpenCFD (`v2012` … `v2606`) |
|---|---|---|
| Solver invocation | `foamRun -solver <module>` (from v11) | one executable per physics, e.g. `interFoam` |
| Fluid properties | `constant/physicalProperties` | `constant/transportProperties` |
| Turbulence | `constant/momentumTransport` | `constant/turbulenceProperties` |
| Restoring initial fields | tutorials usually ship `0/` directly | `restore0Dir` copies `0.orig/` to `0/`, as `Allrun` does here |

`pitzDaily-of13/` and `motorBike-of12/` in this repository show the other side of
that table.

## Case at a glance

| | |
|---|---|
| Solver script | `openFoam-v2412` |
| Suggested vCPU / RAM | 4 / `standard` |
| Mesh | 2 268 hexahedral cells, generated by `blockMesh` at run time |
| Physics | laminar two-phase VOF; water nu = 1e-6 m²/s, rho = 1000 kg/m³; air nu = 1.48e-5 m²/s, rho = 1 kg/m³; sigma = 0.07 N/m |
| Simulated time | 1 s, adjustable time step (maxCo 1, maxAlphaCo 1) |
| Indicative runtime | ~3 s of solver time on 4 vCPU |
| Source | OpenFOAM v2412 tutorial `multiphase/interFoam/laminar/damBreak` — see [Source and credits](#source-and-credits) |

## Files

| File | Purpose |
|---|---|
| `Allrun` | restores `0/`, meshes, initialises the water column, decomposes, runs in parallel and reconstructs |
| `Allclean` | resets the case |
| `0.orig/` | pristine initial conditions (`alpha.water`, `U`, `p_rgh`); `restore0Dir` copies them to `0/` |
| `constant/g` | gravity vector |
| `constant/transportProperties` | the two phases and the surface tension |
| `constant/turbulenceProperties` | laminar |
| `system/blockMeshDict` | tank and obstacle geometry |
| `system/setFieldsDict` | the box that is filled with water at t = 0 |
| `system/controlDict` | application, end time, Courant limits |
| `system/decomposeParDict` | 4 subdomains, `simple` method `(2 2 1)` — **match it to the vCPU you request** |
| `system/fvSchemes`, `system/fvSolution` | discretisation and MULES/PIMPLE settings |
| `system/sampling` | optional interface sampling, included by `controlDict` |

Note the ordering in `Allrun`: `setFields` must run **before** `decomposePar`,
otherwise the water column is written into a mesh that is about to be split.

## Run it on cloudhpc.cloud

1. Compress the **contents** of this folder into `damBreak-v2412.zip` — the
   archive must open directly on `0.orig`, `constant`, `system`, `Allrun`,
   `Allclean`.
2. **STORAGE → Add**: type `damBreak-v2412` in the *Dirname* text box, drop the
   archive in, press **Save**.
3. **SIMULATIONS → Add**:
   - **vCPU** `4`
   - **RAM** `standard`
   - **Folder** `damBreak-v2412`
   - **Script** `openFoam-v2412`
4. **Save**, then watch the log: `blockMesh`, `setFields`, `decomposePar`,
   `interFoam`, `reconstructPar`.
5. Download the results from **STORAGE** when the job reports completion.

## Run it with cloudHPCexec

```bash
cd damBreak-v2412

cloudHPCexec                                                   # interactive menus
cloudHPCexec -batch 4 standard openFoam-v2412 damBreak-v2412   # non-interactive
```

Then follow and collect the job:

```bash
cloudHPCexec -wait 12345
cloudHPCexec -download
```

## What to expect

Twenty reconstructed time directories (every 0.05 s). Colour by `alpha.water` in
ParaView and apply a `Contour` at 0.5 to see the free surface: the column
collapses, the jet climbs the obstacle at around t = 0.25 s and the tank is
sloshing by t = 1 s.

## Restarting and SPOT instances

`controlDict` ships with `startFrom startTime`. If you intend to run on SPOT
instances, change it to

```
startFrom       latestTime;
```

so that an instance reboot resumes from the last written time directory instead
of restarting from zero.
