# pitzDaily-of13 — OpenFOAM 13 · backward-facing step

Turbulent incompressible flow over the Pitz–Daily backward-facing step: air enters a
short inlet channel, separates over a sudden expansion and reattaches further
downstream. It is the reference tutorial for validating a steady/transient
incompressible setup, and it runs in about a minute, which makes it a good first
job to fire at a fresh cloudHPC account.

The case also shows what changed with **OpenFOAM 11 and later**: the Foundation
releases no longer ship one executable per physics (`simpleFoam`, `pisoFoam`, …).
A single `foamRun` application loads a *solver module* chosen in `controlDict`:

```
solver          incompressibleFluid;
```

Compare this with `motorBike-of12/`, which still runs `foamRun` but with the
OpenFOAM 12 dictionary layout, and with `damBreak-v2412/`, which follows the
ESI/OpenCFD lineage where per-physics executables such as `interFoam` are alive
and well.

## Case at a glance

| | |
|---|---|
| Solver script | `openFoam-of13` |
| Suggested vCPU / RAM | 4 / `standard` |
| Mesh | 12 225 hexahedral cells, generated by `blockMesh` at run time |
| Physics | incompressible RAS, k–epsilon, nu = 1e-5 m²/s |
| Simulated time | 0.3 s, adjustable time step (maxCo 5) |
| Indicative runtime | ~15 s of solver time on 4 vCPU |
| Source | OpenFOAM 13 tutorial `incompressibleFluid/pitzDaily` — see [Source and credits](#source-and-credits) |

## Files

| File | Purpose |
|---|---|
| `Allrun` | meshes, decomposes, runs in parallel and reconstructs — the script cloudHPC executes |
| `Allclean` | resets the case to its initial state |
| `0/` | initial and boundary conditions (`U`, `p`, `k`, `epsilon`, `nut`, `nuTilda`) |
| `constant/physicalProperties` | kinematic viscosity |
| `constant/momentumTransport` | turbulence model selection |
| `system/blockMeshDict` | the step geometry and its grading |
| `system/controlDict` | solver module, end time, write control |
| `system/decomposeParDict` | number of subdomains — **keep it equal to the vCPU you request** |
| `system/fvSchemes`, `system/fvSolution` | discretisation and linear solver settings |
| `system/functions` | inlet patch averages written during the run |

Unlike the upstream tutorial, `system/blockMeshDict` is included in the case
instead of being read from `$FOAM_TUTORIALS`, so the folder is self-contained.

## Run it on cloudhpc.cloud

1. Compress the **contents** of this folder (`0`, `constant`, `system`, `Allrun`,
   `Allclean`) into `pitzDaily-of13.zip` — opening the archive must show those
   entries directly, not a `pitzDaily-of13/` wrapper.
2. Go to **STORAGE → Add**, type `pitzDaily-of13` in the *Dirname* text box to
   create the folder, drop the archive in the *File* box and press **Save**.
   The platform unpacks it for you.
3. Go to **SIMULATIONS → Add** and set:
   - **vCPU** `4` — the same number as `numberOfSubdomains`
   - **RAM** `standard`
   - **Folder** `pitzDaily-of13`
   - **Script** `openFoam-of13`
4. Press **Save**. Follow the job from the simulation list; the live log shows
   `blockMesh`, `decomposePar`, the `foamRun` iterations and `reconstructPar`.
5. When it finishes, download the results from **STORAGE** and open the
   reconstructed time directories in ParaView.

## Run it with cloudHPCexec

[`cloudHPCexec`](https://github.com/CFD-FEA-SERVICE/CloudHPC/blob/master/exampleAPI/cloudHPCexec)
compresses the current directory, uploads it and launches the job in one shot.

```bash
cd pitzDaily-of13

# interactive: pick vCPU, RAM and solver from the menus
cloudHPCexec

# or non-interactive: vCPU, RAM, script, storage folder
cloudHPCexec -batch 4 standard openFoam-of13 pitzDaily-of13
```

The command prints the simulation ID. From there:

```bash
cloudHPCexec -wait 12345        # block until the job is over
cloudHPCexec -ssh  12345        # shell into the running instance
cloudHPCexec -download          # fetch and unpack the results
```

## What to expect

The recirculation bubble behind the step reattaches at roughly six step heights.
`postProcessing/` holds the inlet pressure and velocity averages requested in
`system/functions`, and the reconstructed `0.01 … 0.3` time directories contain
the fields for ParaView.

## Scaling it up

Raise `numberOfSubdomains` in `system/decomposeParDict` and request the matching
vCPU count. At 12 225 cells this case is far too small to benefit from more than
a handful of cores — refine `system/blockMeshDict` first, or move to
`motorBike-of12/` for a genuinely parallel workload.

Changes made for cloudHPC:

- `system/blockMeshDict` copied into the case, so the folder no longer depends
  on `$FOAM_TUTORIALS` being reachable at run time
- `system/decomposeParDict` added (4 subdomains, `scotch`)
- `Allrun` extended with `decomposePar`, `runParallel foamRun` and
  `reconstructPar` — the upstream script runs in serial
- `Allclean` added

The geometry and flow conditions go back to the turbulent mixing-layer
experiment of R. W. Pitz and J. W. Daily, *Combustion in a turbulent mixing
layer formed at a rearward-facing step*, AIAA Journal 21(11), 1983.
